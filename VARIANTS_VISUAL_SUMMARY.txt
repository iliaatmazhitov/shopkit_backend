📊 BEFORE vs AFTER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ BEFORE (Simple Attributes):
┌─────────────────────────────────────────────────────────────────────┐
│ products table                                                      │
├─────────────────────────────────────────────────────────────────────┤
│ product_id: "uuid-1"                                               │
│ title: "iPhone 15 Pro"                                             │
│ price: 100000  ← ONE PRICE FOR ALL                                │
│ stock_count: 5  ← ONE STOCK FOR ALL                               │
│ image_url: "iphone.jpg"  ← ONE IMAGE FOR ALL                      │
│ attributes: {"storage": "128GB"}  ← JUST METADATA                  │
└─────────────────────────────────────────────────────────────────────┘

PROBLEM: Can't have different prices/images/stock for 128GB vs 256GB!

✅ AFTER (Product Variants System):
┌─────────────────────────────────────────────────────────────────────┐
│ products table (BASE PRODUCT)                                       │
├─────────────────────────────────────────────────────────────────────┤
│ product_id: "uuid-1"                                               │
│ title: "iPhone 15 Pro"                                             │
│ description: "Latest iPhone model"                                  │
│ category: "Electronics"                                             │
└─────────────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────┼───────────────┬───────────────┐
              │               │               │               │
              ▼               ▼               ▼               ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ VARIANT 1        │ │ VARIANT 2        │ │ VARIANT 3        │ │ VARIANT 4        │
├──────────────────┤ ├──────────────────┤ ├──────────────────┤ ├──────────────────┤
│ 128GB Black      │ │ 256GB Black      │ │ 128GB White      │ │ 256GB White      │
│ 100,000₽         │ │ 120,000₽         │ │ 100,000₽         │ │ 120,000₽         │
│ 5 in stock       │ │ 3 in stock       │ │ 0 in stock ❌    │ │ 8 in stock       │
│ black-128.jpg    │ │ black-256.jpg    │ │ white-128.jpg    │ │ white-256.jpg    │
└──────────────────┘ └──────────────────┘ └──────────────────┘ └──────────────────┘

SOLUTION: Each variant has own price/image/stock/description!


🗄️ DATABASE STRUCTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌─────────────────────────────────────────────────────────────┐
│ products (BASE PRODUCTS)                                    │
├─────────────────────────────────────────────────────────────┤
│ • id (SERIAL PRIMARY KEY)                                   │
│ • product_id (UUID UNIQUE)  ← Main identifier              │
│ • shop_id (INTEGER) → references shops                      │
│ • title (VARCHAR)  ← Base product name                     │
│ • description (TEXT)                                        │
│ • category (VARCHAR)                                        │
│ • tags (TEXT[])                                            │
│ • is_active (BOOLEAN)                                       │
│ • created_at, updated_at (TIMESTAMP)                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ 1:N relationship
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ product_variants (VARIANTS)                                 │
├─────────────────────────────────────────────────────────────┤
│ • id (SERIAL PRIMARY KEY)                                   │
│ • variant_id (UUID UNIQUE)  ← Variant identifier           │
│ • product_id (UUID) → references products(product_id)       │
│ • sku (VARCHAR) - Stock Keeping Unit                        │
│ • title (VARCHAR)  ← Variant-specific title                │
│ • price (INTEGER)  ← Variant price in kopeks               │
│ • currency (VARCHAR)                                        │
│ • image_url (TEXT)  ← Variant-specific image               │
│ • description (TEXT)  ← Variant-specific description        │
│ • stock_count (INTEGER)  ← Variant stock                    │
│ • attributes (JSONB)  ← {"size": "42", "color": "Black"}   │
│ • is_active (BOOLEAN)                                       │
│ • is_default (BOOLEAN)  ← Mark default variant             │
│ • sort_order (INTEGER)  ← Custom ordering                   │
│ • created_at, updated_at (TIMESTAMP)                        │
└─────────────────────────────────────────────────────────────┘

🚀 MIGRATION PROCESS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: Backup
┌────────────────────────────────────────────────────────────────┐
│ pg_dump $DATABASE_URL > backup.sql                             │
└────────────────────────────────────────────────────────────────┘

Step 2: Run Migration
┌────────────────────────────────────────────────────────────────┐
│ psql $DATABASE_URL < sql/migrations/002_migrate_to_variants.sql│
└────────────────────────────────────────────────────────────────┘

What happens:
  1. ✅ Rename products → products_old (backup)
  2. ✅ Create new products table (base products)
  3. ✅ Create product_variants table
  4. ✅ Migrate data: each old product → base + 1 variant
  5. ✅ Create indexes (GIN, B-tree)
  6. ✅ Create VIEW products_with_default_variant
  7. ✅ Setup triggers for auto-update timestamps
  8. ✅ Keep products_old for safety

Step 3: Verify
┌────────────────────────────────────────────────────────────────┐
│ SELECT COUNT(*) FROM products;                                 │
│ SELECT COUNT(*) FROM product_variants;                         │
│ -- Counts should match                                         │
│                                                                │
│ SELECT * FROM products_with_default_variant LIMIT 5;           │
└────────────────────────────────────────────────────────────────┘

Step 4: Rollback (if needed)
┌────────────────────────────────────────────────────────────────┐
│ DROP TABLE product_variants CASCADE;                           │
│ DROP TABLE products CASCADE;                                   │
│ ALTER TABLE products_old RENAME TO products;                   │
└────────────────────────────────────────────────────────────────┘
